# 桌面首次命名

Stop Hook 在轮次结束后调用独立模型。后台已保存标题时，正在打开的桌面侧栏有时仍显示旧标题。Codex 桌面提供宿主工具时，当前对话可以在回复前直接拟定并写入首次标题。后台 Hook 仍可处理后续轮次。

## 可选配置

将以下内容追加到当前生效的全局 Codex 指令文件，通常是 `~/.codex/AGENTS.md`。用新对话验证。移除该段即可停用桌面规则。

```markdown
## Codex 桌面首次命名

- 仅为当前本地 Codex 桌面对话首次命名。用户第一次说清具体对象和目标时，在正常回复前调用宿主工具 `mcp__codex_app__set_thread_title`。省略 threadId，使用当前对话作为目标。
- 用户已指定标题、当前标题已经符合「emoji 对象｜目标」且准确、或本对话曾用宿主工具命名时，保留现有标题。问候、确认和主题不清楚时等待。
- 首次命名前只读检查插件的 `config.json` 和 `threads/<当前线程 ID>.json`。数据目录默认为 `~/.codex/oil-codex-title`，有自定义目录时沿用插件配置。发现 enabled 为 false、locked 为 true，或无法确认已有文件的状态时跳过。状态文件不存在时沿用插件默认值。
- 标题跟随用户语言，采用「emoji 对象｜目标」，省略外层项目名和私人信息。工具不可用时继续原任务，由 Stop Hook 后备处理。完成写入后直接处理用户原任务。
```

例如用户请求修复 CSV 导出重复表头，可以命名为「🧩 CSV 报表导出｜修复重复表头」。

## 验证范围

Windows 已验证通过宿主工具写入和从宿主列表读回标题。规则依赖当前对话加载全局指令并能调用宿主工具，自动触发的稳定性仍待单独验证。后台 Stop Hook 后续改名仍受桌面刷新机制影响。
